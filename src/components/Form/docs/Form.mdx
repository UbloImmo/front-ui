## Usage

Forms are tricky. There are a lot of prerequisites needed for them to be great to use.

Our `Form` component is our try at simplifying the whole experience, both for our users and collaborators.
Built around our very own [Field](?path=/docs/components-forms-field-usage--docs) component,
it handles both edition and consultation of various data structures while providing ease of user.

> You'll be looking at a simple address form in the majority of the upcoming examples;
>
> <br />
> Though you're welcome to look at [additional examples](?path=/docs/components-forms-form-examples--docs)

### Switching between edition & consultation

A form's default behaviour is to first present its data in an easily readable manner, and allow users to edit when its `Edit` button has been clicked.

Some information may however only be edited under certain conditions. To restrict edit access, use the `readonly` property.
If you want to save your users a click, a form can be made editable from the get-go by setting its `defaultEditing` property to `true`.
While you can easily customize the behaviour of individual form fields and disable them all, an easier way to achieve this is to set the `disabled` property on the form itself.

> In order: default behaviour, `readonly`, `defaultEditing` & `disabled`

#### Dynamic content

Some forms may need to update their contents based on either external or external state changes.

##### External state

The Form component's `content` property is reactive. Any changes to it will trigger a complete re-render.

It can therefore easily respond to external changes:

```tsx
import { Form, Callout, Button } from "@ubloimmo/uikit";
import { useState, useMemo } from "react";


const MyForm = () => {
  const [showCallout, setShowCallout] = useState(false);

  // content is re-computed when showCallout is updated
  const content = useMemo(() => [
    {
      kind: "content",
      content: showCallout ? <Callout>this is a callout</Callout> : null,
    }
  ], [showCallout]);

  return (
    <>
      <Form title="My Form" content={content} />
      <Button onClick={() => setShowCallout(true)} label="Show callout inside form" />
    </>
  );
}
```

##### Internal state

Reacting to internal state changes (e.g. whether the form is in editing or reading mode, its current data, etc...) can get trickier without having access to its internal context during content declaration.

###### Complete reactivity

To react to internal state changes, declare `content` as a callback function:

```tsx
import { Form, Callout, type FormComputedContentFn } from "@ubloimmo/uikit";
import { useCallback } from "react";

type MyFormData = {
  showCallout: boolean;
}

const MyForm = ({ bottomText }: { bottomText: string }) => {
  // content is a function that returns a content array
  // and gets re-ran each time the form's internal state changes
  const content = useCallback<FormComputedContentFn<MyFormData>>(
    (context) => [
      {
        kind: "feature-switch",
        source: "showCallout",
        variant: "switch",
        label: "Show callout ?"
      },
      {
        kind: "content",
        content: context.data.showCallout ? <Callout>this is a callout</Callout> : null,
      },
      {
        kind: "text",
        content: bottomText,
      }
    ],
    // external state changes also trigger the content to be re-computed
    [bottomText]
  );

  return (
      <Form<MyFormData> title="My Form" content={content} />
  );
}
```

> Please refer to [this example](?path=/story/components-forms-form-stories--computed-content) for a more complete demo.

###### Granular reactivity

Performance may take a hit when re-computing a large content array in this manner when the Form's internal state changes.

Fined-grained reactivity can be achieved by declaring indiviual array items as callback functions:

```tsx
import { Form, Callout, type FormContentArray } from "@ubloimmo/uikit";
import { useMemo } from "react";

type MyFormData = {
  showCallout: boolean;
}

const MyForm = ({ bottomText }: { bottomText: string }) => {
  // content is an array the holds both static objects & callback functions that return a single content item or null
  // and gets re-ran each time the form's internal state changes
  const content = useMemo<FormContentArray<MyFormData>>(
    ) => [
      {
        kind: "feature-switch",
        source: "showCallout",
        variant: "switch",
        label: "Show callout ?"
      },
      (context) => context.data.showCallout ? ({
        kind: "content",
        content: <Callout>this is a callout</Callout>,
      }) : null,
      {
        kind: "text",
        content: bottomText,
      }
    ],
    // external state changes also trigger the content to be re-computed
    [bottomText]
  );

  return (
      <Form<MyFormData> title="My Form" content={content} />
  );
}

> Please refer to [this example](?path=/story/components-forms-form-stories--partial-computed-content) for a more complete demo.



#### Data Validation

User data can be error-prone. Form supports data validation through `zod` schemas.
Provide it as a form's `schema` property for it to be used to validate user- or initial data.

#### Data fetching

To fetch existing data to be displayed inside a form, provide it with a `query` property.

```tsx
import { Form, arrayOf } from "@ubloimmo/uikit";

// async function that returns at least partial data
const fetchAsyncData = async () => {
  const res = await fetch("/api/data");
  return await res.json();
};

const MyAsyncForm = () => <Form query={fetchData} />;

// non-async function that return data
const generateData = (numberCount: number) => ({
  randomNumbers: arrayOf(numberCount, () => Math.random()),
});

const MyGeneratedForm = () => <Form query={generateData} />;

// static data object
// this could also be derived from a state
const staticData = {
  firstName: "John",
  lastName: "Doe",
};

const MyStaticForm = () => <Form query={staticData} />;
```

#### Handling data updates

The form will refetch its own data using the provided `query` object or function every time it changes.

By default, newly loaded data will be merged with the form's existing data if present, either because of exisiting user edits, or previous loads.
This behavior can be turned controlled through the `shouldMergeQueryData` property. By setting it to `false`, newly loaded data will completely overwrite the form's current internal data.

#### Forcing updates based on external changes

An optional `reloadKey` property may be provided. When its value changes, it will trigger a complete reload of the form's data, regardless of the value of `shouldMergeQueryData`, behaving as if it is set to `false`.

> This may be useful for reloading the form when e.g. the window's URL changes but the form doesn't get re-rendered.
